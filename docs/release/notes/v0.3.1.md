# TensorPlate v0.3.1 release notes

> Draft for the final release owner. Do not publish the final `v0.3.1`
> release until the tag, artifacts, checksums, Production-row lifecycle
> evidence, and sign-off are complete. Release candidates publish without
> that evidence on purpose — see "Validation status" below.

TensorPlate v0.3.1 is the first release of the 0.3 line. Its goal is
streaming speech-to-text and text-to-speech on a single NVIDIA L4 host,
served to an application on the same machine.

**The release candidates do not serve streaming speech yet.** They carry
the groundwork that feature is built on, and they are published so that
the install, upgrade and rollback lifecycle and the two candidate speech
runners can be measured on real hardware. Do not read a candidate as a
speech release.

## Added so far

The complete list, with file-level detail, is the `0.3.1` section of
[`CHANGELOG.md`](../../../CHANGELOG.md).

- **Candidate speech runners.** The Python sidecar gains two runner
  profiles, `faster_whisper` (speech-to-text) and `kokoro`
  (text-to-speech). Each loads a model family from a bundle's own files and
  takes languages, voices and sample rate from the bundle's declaration.
  They run on the existing request/response path and are marked candidate
  only: they exist to be measured, not yet to be deployed.
- **Bundle format 0.2, opt-in.** A manifest can declare
  `"format_version": "0.2"` with a speech contract, per-domain memory
  budgets and a runner profile. Format 0.2 manifests are validated by rule,
  with typed reasons for each refusal. Readers accept exactly formats 0.1
  and 0.2; format 0.1 bundles are unchanged.
- **A deployment descriptor** records what the agent verified for one
  generation of one deployment, with separate digests for the portable
  configuration and for the running instance.
- **Bundle provisioning.** `tensorplate bundle provision` retrieves a
  manifest-listed bundle with digest verification, resumes an interrupted
  fetch, and changes nothing on a repeat run. Pinned reference manifests
  for the two candidate model sets are included.
- **Session and control groundwork.** A logical streaming session has a
  defined lifecycle and a manager with idle, heartbeat, liveness and
  duration limits; the agent and the serving worker gain a control
  channel with a shared message schema. These are built and tested as
  components and are not yet connected to a serving endpoint.
- **Memory observation.** The agent can be configured with per-domain
  memory caps and reserves, and an operator tool samples host and
  accelerator memory over a bounded window.
- **A candidate qualification tool,**
  `tools/validation/candidate-qualify.py`, which deploys a candidate
  bundle, times it, samples its memory, drives its negative paths, tears
  it down and writes one machine-readable record.
- **Supply-chain and publication checks** in CI: dependency policy,
  SBOMs and vulnerability audit, and scanners that keep host and
  account identifiers out of committed evidence.

## Changed behaviour to know before upgrading

- The agent refuses a control request that carries a field it does not
  know, a payload that belongs to another operation, or an explicit
  `null`, instead of ignoring it. Every request earlier CLIs and the SDK
  send is still accepted.
- The agent no longer falls back to `state.json.bak` when `state.json`
  is refused for an unsupported state version or cannot be read at all;
  it stops instead. A damaged, empty or missing `state.json` still falls
  back as before.
- The agent's durable state file gains state version `0.2`.
- On a Compute Engine instance, the agent records which instance its
  machine-type record belongs to, and the documented rollback restores
  that record.

The `Changed`, `Fixed` and `Security` blocks of the changelog list the
rest.

## Not in the candidates

- No streaming transport and no streaming speech serving.
- The speech runtime package family (`tensorplate-speech-runtime-*`) is
  defined in the source tree, and no release builds or attaches it. A
  candidate's assets are the core runtime packages only, and
  `install.sh --with-speech-runtime` refuses a release that lists no such
  package.
- No Production support claim for speech on any platform row.

## Validation status

No Production platform row carries v0.3.1 lifecycle evidence yet. The rows
name `docs/validation/evidence/v0.3.1/<row>/` as the place it will be
filed, and the release workflow's evidence gate blocks a **final** tag
until every Production row carries a recorded, passing lifecycle report
for this version. Candidates are not gated, because the evidence can only
come from one: the harnesses validate published candidate artifacts.

The CUDA baseline recorded for the `ubuntu2404-x86-l4-g2s8` row under
`docs/validation/evidence/v0.2.1/` was taken against the published
`v0.2.1` packages and stays there.

## Channel availability

A candidate reaches none of the stable channels (APT, PyPI, Homebrew tap).
A final tag is a necessary condition for each of them, and every publish
job runs in a reviewer-gated environment.

## Supported environment

Unchanged from v0.2.1: Jetson Orin on JetPack 6.x, Ubuntu 24.04 on
`x86_64`, and macOS 26 on Apple silicon, per
[`docs/release/support-matrix.md`](../support-matrix.md).

## Assets

The same set as v0.2.1 under this version: the `arm64` and `amd64` runtime
packages, `tensorplate-backend-python-pytorch`, `tensorplate-apt-source`,
the Python SDK wheel and sdist, `install.sh`, the artifact manifest,
`SHA256SUMS` and `SHA256SUMS.cosign.bundle`. A release candidate carries
them under the candidate's version spellings: `0.3.1~rc.N` for Debian
packages (file names spell it `0.3.1.rc.N`), `0.3.1rcN` for the SDK, and
the tag `v0.3.1-rc.N` in the manifest name.
