# TensorPlate v0.1.2 release notes

> Draft for the final release owner. Do not publish until the `v0.1.2`
> tag, artifacts, checksums, validation evidence, clean-room evidence, and
> sign-off are complete.

TensorPlate v0.1.2 makes package managers the primary install path. On a
TensorPlate-ready Jetson, the full runtime install is now:

```bash
sudo apt update
sudo apt install tensorplate
```

## Package-manager support added in this release

- **Stable signed APT repository** at
  `https://packages.tensorplate.com/apt` (`jammy/main`, `arm64` and
  `amd64`). Repository metadata is signed; APT verifies it against the
  keyring shipped by `tensorplate-apt-source`. The repository is
  generated exclusively from checksum- and cosign-verified release
  assets.
- **`tensorplate-apt-source`** — one-time bootstrap package installing
  only the archive keyring and the Deb822 source for the stable channel.
  Stock Ubuntu/Jetson hosts install it once (APT cannot discover
  TensorPlate before this); TensorPlate-ready images ship it
  preinstalled. Future releases then arrive through normal
  `apt update` / `apt upgrade` with no repeated setup.
- **`tensorplate` metapackage** (Jetson `arm64`) — installs the complete
  runtime set: agent, serving worker, observability, CLI, and shared
  helpers. The optional Python/PyTorch backend stays a separate,
  suggested package.
- **`tensorplate-cli` for Ubuntu AMD64** — CLI-only workstation install
  from the same repository: `sudo apt install tensorplate-cli`.
- **First-party Homebrew tap** for macOS Apple Silicon (CLI-only):
  `brew install tensorplate/tap/tensorplate`.

Upgrading a v0.1.1 host (installed from GitHub Release assets): install
the bootstrap package from this release's assets, then run the two
commands above — packages upgrade in place with configuration and state
preserved. Full flow:
[`docs/install/tensorplate-ready.md`](../../install/tensorplate-ready.md).

## Limitations

- The runtime remains Jetson `arm64` only; `amd64` and macOS receive the
  operator CLI only. No macOS runtime service exists by design.
- The APT channel publishes final releases only; release candidates are
  never published to the stable repository.
- The Homebrew formula requires the tap (`tensorplate/tap`); plain
  `brew install tensorplate` from `homebrew/core` is not supported. The
  formula builds from source on Apple Silicon; bottles are follow-up
  work.
- The repository serves Ubuntu 22.04 (`jammy`) suites; other
  distributions remain on the GitHub-assets fallback.

## Fallback artifact source

GitHub Release assets remain fully supported and remain the
checksum-covered, cosign-signed source of truth: every `.deb`,
`install.sh`, the artifact manifest, `SHA256SUMS`, and
`SHA256SUMS.cosign.bundle` are attached to this release, and the APT
repository itself is reproducible from them. Verification commands:
[`SECURITY.md`](../../../SECURITY.md).

## Supported environment

- Jetson Orin Nano 8GB Super hardware floor.
- JetPack 6.x with L4T 36.x.
- `arm64` Debian packages via the APT channel or attached to this GitHub
  Release; `amd64` CLI-only package; macOS Apple Silicon CLI via
  Homebrew.
- Local-only default endpoints through Unix sockets and loopback.
