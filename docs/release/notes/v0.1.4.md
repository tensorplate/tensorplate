# TensorPlate v0.1.4 release notes

> Draft for the final release owner. Do not publish until the `v0.1.4`
> tag, artifacts, checksums, validation evidence, clean-room evidence, and
> sign-off are complete.

TensorPlate v0.1.4 adds an optional **binary `/infer` transport** to the
serving worker and the `tensorplate-python` SDK, and a new **YOLO26
end-to-end detection contract** in the SDK. Both are backward compatible:
the v0.1 serving HTTP envelope (`schema_version` `0.1`) is unchanged, the
JSON path is unchanged, and the agent, CLI, deploy / rollback / doctor, and
APT / Homebrew install paths are unchanged from v0.1.3.

```python
import tensorplate

# Binary transport is negotiated automatically; falls back to JSON.
client = tensorplate.VisionClient("http://127.0.0.1:18080")
detections = client.detect(
    "frame.jpg", endpoint="yolo26n", contract=tensorplate.YOLO26_E2E_DETECTIONS
)
```

The SDK installs from PyPI (`pip install tensorplate-python`); the wheel +
sdist are also attached to this GitHub Release (cosign-signed, listed in
`SHA256SUMS`) for checksum-verified or air-gapped installs.

## Added in this release

- **Binary `/infer` transport** (serving worker + Python SDK) — an optional,
  content-type-negotiated wire format
  (`application/vnd.tensorplate.infer.binary.v1`) that frames tensor payloads
  as raw bytes (8-byte magic, little-endian `uint32` metadata length, metadata
  JSON, then concatenated payloads) instead of base64, cutting request encode
  cost and payload size for large vision inputs. It is opt-in and fully
  backward compatible: a worker that does not accept the binary content-type
  replies `415`, so `auto`-transport SDK clients transparently fall back to
  JSON. The wire framing is documented in
  [`serving_http_envelope.json`](../../../protocol/schemas/serving_http_envelope.json).
- **YOLO26 E2E detection SDK contract** (`YOLO26_E2E_DETECTIONS` /
  `yolo26_e2e_detections`) — decodes the Ultralytics YOLO26 default
  one-to-one / end-to-end detection head, an NMS-free `[1, K, 6]` tensor, via
  `decode_detections` and `VisionClient.detect`. The `yolo_v8_single_output`
  contract remains the default. `--contract` wiring was added to the vision
  examples and the detection benchmark.

Documentation: [`docs/sdk/`](../../sdk/) — the detection workflow and output
contracts ([`detection.md`](../../sdk/detection.md)) and the SDK API
([`python.md`](../../sdk/python.md)).

## Limitations

- The binary transport is a performance option for tensor payloads; it
  carries the same v0.1 envelope semantics as JSON and changes no protocol
  version, route, or result shape.
- The YOLO26 contract decodes the default end-to-end detection head only;
  segmentation, pose, OBB, and open-vocabulary heads remain
  application-side postprocessing.
- The SDK calls already-deployed models; it does not deploy, run, or change
  runtime serving. Runtime limitations from v0.1.3 are otherwise unchanged.

## Fallback artifact source

Besides PyPI, the SDK wheel and sdist are attached to this GitHub Release and
covered by the same `SHA256SUMS` and `SHA256SUMS.cosign.bundle` as the runtime
packages — use this for checksum-verified or air-gapped installs. Verification

[`docs/install/external-install.md`](../../install/external-install.md).

## Supported environment

- Runtime targets are unchanged from v0.1.3: Jetson Orin Nano 8GB Super
  hardware floor; JetPack 6.x with L4T 36.x; `arm64` runtime packages via the
  APT channel or attached to this GitHub Release; `amd64` CLI-only package;
  macOS Apple Silicon CLI via Homebrew.
- The SDK is a pure-Python client (`py3-none-any`) for Python 3.10+ on any
  platform, targeting a reachable TensorPlate serving endpoint.
- Local-only default endpoints through Unix sockets and loopback.
