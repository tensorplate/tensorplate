# TensorPlate v0.1.3 release notes

> Draft for the final release owner. Do not publish until the `v0.1.3`
> tag, artifacts, checksums, validation evidence, clean-room evidence, and
> sign-off are complete.

TensorPlate v0.1.3 adds the first-party Python SDK, `tensorplate-python`
(import package `tensorplate`) — a typed, client-side library for calling
detectors you have already deployed, over the v0.1 serving `/infer` HTTP
envelope. The runtime, serving worker, CLI, and APT / Homebrew install
paths are unchanged from v0.1.2.

```python
import tensorplate

client = tensorplate.VisionClient("http://127.0.0.1:18080")
detections = client.detect("frame.jpg", endpoint="yolov8n")
```

Install it from PyPI:

```bash
pip install tensorplate-python            # core client
pip install "tensorplate-python[vision]"  # + numpy & Pillow for VisionClient.detect
```

The same wheel + sdist are also attached to this GitHub Release
(cosign-signed, listed in `SHA256SUMS`) for checksum-verified or air-gapped
installs. Install details and quickstart:
[`docs/sdk/python.md`](../../sdk/python.md).

## Python SDK added in this release

- **`ServingClient`** — schema-valid `InferRequest` marshalling with
  base64 tensor payloads, success / failure parsing into typed results and
  exceptions, `schema_version` enforcement, a `GET /health` readiness
  snapshot, and serving endpoint resolution matching the CLI precedence and
  URL canonicalization.
- **Vision helpers** (the `tensorplate-python[vision]` extra — numpy +
  Pillow) — client-side preprocessing (letterbox to NCHW float32, recording
  the transform for source-pixel box mapping) and YOLOv8-style
  postprocessing (`decode_detections`, class-aware NMS, the
  `yolo_v8_single_output` contract, and the `detections.*` convention). The
  core install is dependency-free.
- **`VisionClient.detect`** — one call from a path, `bytes`, or ndarray to
  source-pixel `Detection`s, with configurable endpoint, input / output
  names, thresholds, labels, and contract. Synchronous in v0.1.3.
- **Examples** under
  [`examples/vision_detection_sdk/`](../../../examples/vision_detection_sdk/)
  — a single-image detector and a user-space `camera → SDK → /infer`
  reference loop. Samples, not a supported runtime surface.
- **Packaged and attested as a signed release artifact** — the wheel and
  sdist are built at the release version, folded into the cosign-signed
  `SHA256SUMS` and the artifact manifest, and attached to this release with
  build provenance.

Documentation: [`docs/sdk/`](../../sdk/) — quickstart and API

## Limitations

- The SDK is synchronous request / response. In-runtime camera ingest, a
  DeepStream sink, and a streaming API are out of scope and remain deferred
  runtime capabilities; the camera example runs in your own process.
- The SDK calls already-deployed models; it does not deploy, run, or change
  runtime serving.
- Runtime limitations from v0.1.2 are unchanged.

## Fallback artifact source

## Supported environment

- The SDK is a pure-Python client (`py3-none-any`) for Python 3.10+ on any
  platform, targeting a reachable TensorPlate serving endpoint.
- Runtime targets are unchanged from v0.1.2: Jetson Orin Nano 8GB Super
  hardware floor; JetPack 6.x with L4T 36.x; `arm64` runtime packages via
  the APT channel or attached to this GitHub Release; `amd64` CLI-only
  package; macOS Apple Silicon CLI via Homebrew.
- Local-only default endpoints through Unix sockets and loopback.
