# Versioning

TensorPlate v0.1.0 maintains four independent version surfaces. Components
that exchange data must declare what they speak (and what they accept) so
mismatches surface as typed errors instead of undefined behavior.

> Public-contract changes require a `CHANGELOG.md` entry and the matching
> version bump below. See
> [`CONTRIBUTING.md`](../../CONTRIBUTING.md#release-and-changelog-policy).

## The four surfaces

| Surface | What it versions | Owner | Source of truth |
| --- | --- | --- | --- |
| Runtime version | The C++ runtime, serving worker, and adapter implementations. | Runtime tech lead | `project()` in `CMakeLists.txt`; surfaced via `tensorplate::kRuntimeVersion`. |
| Protocol version | Cross-process schemas in `protocol/schemas/` (request/response, worker status, health events, deploy transaction state). | Runtime + agent | `tensorplate::kProtocolVersion` (C++) / `tensorplate_protocol::PROTOCOL_VERSION` (Rust). |
| Schema version | Per-schema `schemaVersion` field in `config/schemas/` and `protocol/schemas/`. | Schema author | The schema file itself. |
| Bundle format version | Layout of the deployable model bundle described in bundle format. | Agent owner | `tensorplate::kBundleFormatVersion` and the `bundleFormatVersion` field in the bundle manifest. |

These surfaces evolve at independent cadences. A runtime patch release does
not imply a protocol or bundle bump, and vice versa.

## Where the constants live

- C++: [`include/tensorplate/version.hpp`](../../include/tensorplate/version.hpp)
  is generated by CMake from `version.hpp.in`. The runtime triple comes
  from `project(TensorPlate VERSION ...)`. Protocol and bundle-format
  numbers come from `TP_PROTOCOL_VERSION_*` and
  `TP_BUNDLE_FORMAT_VERSION_*` cache entries in the root `CMakeLists.txt`.
- Rust: `tensorplate_protocol::{PROTOCOL_VERSION, BUNDLE_FORMAT_VERSION,
  ...}` mirror the C++ constants. The `version()` function returns the
  *crate* version (`CARGO_PKG_VERSION`) - the runtime release version, not
  the protocol version.
- Schemas (when they land in V01-E02): every schema file declares a
  top-level `schemaVersion` string. The runtime and agent reject unknown
  versions with a typed error.

Until the schema files exist, the C++ `Version*` tests in
[`test/unit/version_test.cpp`](../../test/unit/version_test.cpp) and the
Rust `version_*` tests in
[`protocol/rust/src/lib.rs`](../../protocol/rust/src/lib.rs) verify that
the component fields and composed strings agree on each side. Drift between
languages is caught the moment a schema file lands and both implementations
read from it.

## Bumping rules

### Runtime version

- **Patch** (`0.1.0 -> 0.1.1`): bug fixes only, no public header changes,
  no behavior changes that callers can observe.
- **Minor** (`0.1 -> 0.2`): additive changes to public types under
  `include/tensorplate/`, new error codes, new config fields with safe
  defaults.
- **Major** (`0.x -> 1.0`): any change that breaks compiled callers of
  `include/tensorplate/`, including `ExecutionSession` method signatures.

`include/tensorplate/` changes require tech lead approval per
`CONTRIBUTING.md`. `ExecutionSession` method changes additionally require a
written justification.

### Protocol version

- **Minor**: a new optional field, a new optional schema, or an additive
  enum value that older readers can ignore.
- **Major**: removal of a field, change of field type, change of a
  required field's semantics, or any change that older readers cannot
  ignore.

The protocol version moves independently of the runtime version. The
runtime and agent both declare the protocol versions they accept; mismatched
versions are rejected with a typed error during the deploy transaction's
`verified` phase (lands in V01-E02 / V01-E08).

### Schema version

Each schema's `schemaVersion` field follows the same minor/major rules as
the protocol version, scoped to that schema. A bundle manifest at
`schemaVersion 0.2` is acceptable to a runtime that supports schemas
`0.1` and `0.2`; a runtime that only supports `0.1` rejects it with a
typed error rather than guessing.

### Bundle format version

- **Minor**: additive optional fields in the manifest, new optional
  artifact files alongside the existing ones.
- **Major**: changes to the bundle directory layout, mandatory new
  artifacts, or changes to digest semantics.

Bundle format compatibility is validated by the agent during the
`verified` phase before staging.

## Compatibility checks (planned)

The first concrete validations land alongside V01-E02 (`Result<T>` /
`Error` taxonomy) and V01-E08 (deploy transaction). The expected behavior:

- The runtime advertises the runtime, protocol, and bundle format versions
  it supports through its public version constants and through a control
  endpoint.
- The agent reads each bundle's `bundleFormatVersion` and the runtime's
  advertised range during `verified`. Any mismatch produces a typed
  `Unsupported` error and aborts the transaction before staging.
- IPC messages carry their schema version. Mismatches during deploy or
  inference produce a typed `Unsupported` (or `ConfigInvalid` for static
  config) error, never a silent fallback.

## When to bump what

| Change | Runtime | Protocol | Bundle format | Schema |
| --- | --- | --- | --- | --- |
| Bug fix in a runtime adapter | patch | - | - | - |
| Add new C++ value type field with default | minor | - | - | - |
| Remove a `ExecutionSession` method | major | - | - | - |
| Add new optional field to `InferRequest` | - | minor | - | minor (its schema) |
| Change `InferRequest.payload` type | - | major | - | major (its schema) |
| Add `bundle.assets/` optional sidecar dir | - | - | minor | - |
| Re-root the bundle layout | - | - | major | - |

## Drift prevention

Until the schema files become the single source of truth, the C++ and Rust
constants are hand-mirrored. The tests in
`test/unit/version_test.cpp` and the `tests` module in
`protocol/rust/src/lib.rs` verify intra-language consistency. A future
build-time validator (V01-E02) will compare both surfaces against the
schema files and fail the build on drift.
